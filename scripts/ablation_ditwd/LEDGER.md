## Which module carries dit_hidden/dit_depth in global mode

`latent_dit`, **not** `trajectory_dit`. `LatentDiT` is constructed unconditionally at
`models/state_hijacking_dit.py:824-832`; in global mode
(`trajectory_mode: false`, `global_denoiser_type: dit`) the trajectory branch falls
through to `else: self.trajectory_dit = None`. Stage-2 freezing selects the same
module (`train_state_hijacking_dit.py:180-182`): `gdt='dit'` and
`trajectory_mode=False` ⇒ `dit_module = model.latent_dit`, so the diffusion loss
flows into the module whose width/depth we are varying.

## ⚠️ The three rungs do NOT see the same data order (measured)

`DataLoader(shuffle=True)` at `data_simple.py:348-356` is constructed **without**
`generator=`, so the shuffle draws from the global RNG. The global RNG is seeded once
(`train_state_hijacking_dit.py:265-268`, `seed=42+rank`, rank 0 in all runs), but
model init runs between seeding and `next(iter(train_loader))` and consumes a number
of draws that depends on **how many parameters are being initialised**. Different
parameter counts ⇒ different permutation ⇒ different data order.

Measured via the stage-2 sanity CE (`train_state_hijacking_dit.py:552-553`, which
prints the CE of the frozen backbone on the loader's *first* batch — a batch-difficulty
number, not a model property):

| CE | dit | trainable after freeze | log |
|---|---|---|---|
| 3.2851 | 512 / 6 | 375.7M | `abl-ditwd-512x6-scratch.log` |
| 3.5587 | 768 / 8 | 433.1M | `abl-ditwd-768x8-scratch.log` |
| 3.4300 | 1024 / 12 | 575.8M | `abl-ditwd-1024x12-scratch.log` |
| 3.5077 | 768 / 8 | 437.8M | `ctrl50k-dynlowrank.log` |
| 3.2247 | 768 / 8 | 175.1M | `ctrl50k-fixed.log` |

⭐ The driver is **not** DiT width: the two `ctrl50k` rows have *identical* 768/8 DiT
and still differ by 0.28, because their trainable counts differ (437.8M vs 175.1M).
Anything that changes init-time RNG consumption moves the permutation. Our three
rungs' spread (0.27) is the same magnitude as that already-published controlled pair's
(0.28), i.e. this confound is **not specific to this ablation** — it is present in the
ctrl50k pair too.

Scale of the residual effect: `train_batch_size=16` x 50000 steps = 800k samples over
a 304,052-chunk dataset ≈ 2.6 epochs, so order differences are largely averaged out,
but not exactly zero. Report the rungs as an ablation over width/depth **with the data
order not held fixed**; do not attribute small deltas between adjacent rungs to
width/depth alone.

Fixing it properly would mean passing an explicit `generator=` to the train DataLoader,
which changes the data order for *every* existing run and so cannot be retrofitted onto
the published numbers.

### Do not use the sanity CE as a metric

It is the frozen backbone's CE on one random batch. A different value across rungs is
expected and means nothing about the rung. (Also note it is emitted by `print()`, not
the logger, so it appears only in the stdout-redirected `logs/qz/*.log` and **never**
in the hydra `outputs/**/train_state_hijacking_dit.log` — a `grep -rl` over `outputs/`
returns zero hits, which is absence of evidence, not evidence of absence.)

## ⛔ All three died at step 0 — global+dit cannot train the dynamic S1 writer

All three rungs reached the model-init banner, passed the sanity check, and then raised
on the **first** backward, identically:

```
RuntimeError: Joint training produced no nonzero gradient for dynamic S1 writer
modules: s1_trunk, s1_u_head, s1_v_head. Refusing to continue a DiT-only run.
```

This is the repo's own guard (`training.require_s1_writer_grad: true`,
`train_state_hijacking_dit.py:927-945`), firing after `loss.backward()`. All **three**
writer modules were dead at once, and the failure is identical across rungs ⇒ **nothing
to do with width/depth**. Zero checkpoints, zero steps.

### The discriminating evidence

| run | `global_denoiser_type` | guard | logged `s1_grad` | outcome |
|---|---|---|---|---|
| `outputs/2026-09-17/11-04-28` | **birwkv** | **on** | **8.755e-01** (nonzero) | ran 50000/50000 |
| `logs/qz/ctrl50k-dynlowrank.log` | (dit) | off | **0.000e+00** | ran, writer never trained |
| this set, all 3 rungs | **dit** | on | — | ⛔ dies at step 0 |

A full config diff of `11-04-28` against ours leaves exactly one substantive
difference: `global_denoiser_type` **birwkv vs dit** (the others are
`hydra.job.chdir` and `train_batch_size`, which the launcher overrides to 16 anyway).

⇒ The one run that ever trained the dynamic writer with the guard **on** was a
**birwkv** run. Under `dit`, the writer gets no gradient.

⭐ And `ctrl50k-dynlowrank` shows the same thing from the other side: it is a `dit`-path
run that logged `s1_grad=0.000e+00` for its whole life and did **not** crash — because
its `require_s1_writer_grad` was **false**. So a published `dit` arm exists in which the
dynamic S1 writer was **never trained**, and only the disabled guard hid it. This is the
same family as [[silent-inert-loss-terms]] and needs checking against whichever paper
rows came from that checkpoint.

### What is NOT yet established

The gradient path *reads* as connected: `s2_coadapt_ce_loss_weight: 0.5` is on,
`_s2_coadapt_ce_enabled` requires `w>0 ∧ stage==2 ∧ prefix_suffix_s2` and all three hold
(the log prints `Prefix/suffix S2 enabled`), `_singlez_coadapt_ce_from_z` calls
`predict_states` → `_predict_states_dynlowrank` which uses all three writer modules,
`z_0_pred_singlez` is derived from `eps_pred` without `detach()`, and
`inject_into_cache` assigns `st.to(torch.float32)` which keeps the graph.

So **why** the gradient dies is not yet known, and reading more code will not settle it —
it has to be measured. The one structural asymmetry that tracks the birwkv/dit split is in
`inject_into_cache`: `is_rnn_denoiser = global_denoiser_type in ("rwkv","birwkv")`, and the
non-RNN branch (ours) zeroes `conv_state`/`ffn_state`. Zeroing those should not detach
`recurrent_state`, so that is a hypothesis, **not** the answer.

Do not restart these rungs until the writer-gradient question is resolved: with the guard
on they die at step 0, and with the guard off they would train a permanently-dead writer
and silently produce exactly the artefact `ctrl50k-dynlowrank` already is.
